## Design Specificity Verdict

**LLM assessment:** Genuinely authored, not category-interchangeable. The key-prefix reveal warning about keychain permission, the CA card's "created on this machine and never leave it" with the undo path pre-announced, the quit takeover naming exact tools, and the hint-intensity taxonomy (takeover for user toggles, calm banner for restores, sticky error banner for a broken port) structurally realize the reassuring-gatekeeper brief. Remaining weaknesses are follow-through (dead-end pills, contrast, repeat-use friction), not identity.

**Deterministic scan:** 3 findings, all advisory, all previously accepted in .impeccable/critique/ignore.md (two mask-gradient #000s and the tour window's 27px display heading). Zero unaccepted findings; mechanically clean, down from 39 last round.

**Visual overlays:** skipped again; the Chrome extension is not connected, so no browser render or overlay evidence was possible. No processes were started.

## Overall Impression

The identity work landed: the popover now behaves like the product PRODUCT.md describes, and the score moved from Acceptable (25) to Good (31). What remains clusters around one theme: the last mile of truthfulness under stress. The first-run auth path can wedge with no exit, the most important pixel (the pill) fails the AA contrast the product committed to and can't be interrogated when it says "Error", and Home over-reassures when the CA is untrusted. Fix those and the popover earns its pill everywhere, not just on the happy path.

## What's Working

1. **The error-classification seam.** No screen prints String(e); every failure gets a human title, an actionable hint, and the raw payload behind a disclosure. Errors as reassurance opportunities is exactly this brand.
2. **Hint-intensity taxonomy.** Severity of the surface matches severity of the risk (takeover / calm banner / sticky error banner). Few apps get this right.
3. **The stretch-button card pattern.** Drill-in and switch coexist with real semantics and focus rings; keyboard-correct by construction.

## Priority Issues

1. **[P1] OAuth sign-in has no cancel or timeout.** signingIn only clears on error (FirstRun.tsx:49-64; same in Settings handleUpgrade). Abandoning the browser permanently disables the primary button on the very first interaction. **Fix:** Cancel text button while waiting, reset pending login, optional timeout with retry hint. **Command:** /impeccable harden
2. **[P1] Status pills fail WCAG AA.** "Not routed" ink-4 on sunken ~3.5:1, "Routed" #1f8a4c on wash ~3.9:1 at 11px; section labels ink-4 ~4.0:1 (ui.tsx:108, 147, 155; Home.tsx:13, 37). PRODUCT.md commits to AA and calls the pill the most important pixel. **Fix:** darken success-deep, idle pill text to ink-3, decide the section-label stance. **Command:** /impeccable polish
3. **[P1] Tool rows are dead ends.** Error pills truncate their reason in an 11px subtitle with no drill-in, copy, or expansion (Home.tsx:213-227), yet the persona opens the popover precisely to debug a tool. **Fix:** rows with error/drifted status open a sliding detail panel with the classified message and a next step. **Command:** /impeccable shape
4. **[P2] Home hides the untrusted-CA gap.** Green "Routing on" pill while config-less apps silently bypass Gate; the trust card only exists on the Routing screen. **Fix:** warning-tinted routing card state or Home hint when running with CA untrusted. **Command:** /impeccable clarify
5. **[P2] The routing takeover is unsuppressible for daily users.** Every toggle with agents running mounts the takeover; it punishes the day-30 user the metric is named for. **Fix:** degrade repeat same-session occurrences to the inline restart hint. **Command:** /impeccable quieter
6. **[P2] Takeover stacking + background not inert.** aria-modal is set but the background isn't aria-hidden; and if the update check resolves while QuitConfirm is up, UpdateTakeover (z-20) mounts under it (z-30) and its focus trap steals focus into a hidden panel. **Fix:** single-takeover arbitration in App plus background inert. **Command:** /impeccable harden

## Cognitive Load

Failed 2 of 8: chunking (Settings legacy mode stacks 7 sections in one scroll with no tiering) and minimal choices (Settings legacy mode exposes 8 simultaneous actions; OAuth mode 7). Everything else passes, including working memory (hints now persist until dismissed) and progressive disclosure.

- Day-30 repeat use still hits the unsuppressible toggle takeover.
- Quit remains excellent peak-end; Success now closes the loop with "Turn on routing".

## Persona Red Flags

**Alex (Power User):** toggle-then-takeover is his daily tax with no memory; proxyBusy freezes every control with a global wait cursor so he can't queue an action; no mono identifier is copyable; a hiccuped browser sign-in gives him nothing to click.

**Sam (Keyboard/SR user):** Tab/Escape and labeled switches are genuinely solid now. Remaining: no heading/landmark structure outside takeover h1s (SubHeader titles are spans, section labels divs), background not inert under aria-modal, the update-under-quit focus-steal case, "Not routed" pill ~3.5:1, dev "change" link at ink-5 ~2.4:1, Dev mode disclosure without aria-expanded.

**The mid-task developer:** the ledger says "Error" and truncates the reason with no path to a fix; "Drifted" assumes the drift concept mid-panic; if the real problem is an untrusted cert, Home actively reassures them everything is fine.

## Minor Observations

- StartupRoutingNotice now names the opposite of what it does (it is the user-toggle takeover); rename to avoid a maintenance trap.
- Every takeover uses the same shieldCheck glyph, including the "your tools will break" warning; the icon's meaning is diluted.
- Onboarding promises protections (prompt-injection stopped, values redacted) no popover surface ever reflects.
- Empty-tools copy names three tools of seven supported; a Claude Desktop-only user reads "not supported."
- The version footer scrolls with content on tall screens, so the "footer never scrolls" contract is technically broken.
- Tertiary text-button sizes drift between 12px and 12.5px across surfaces.

## Questions to Consider

1. If the pill is the most important pixel, why is it the only element with no next action? What would it mean for "Error" to be a door instead of a verdict?
2. With an untrusted CA the honest answer to "is my traffic routing?" is "some of it." Does reassurance-through-transparency demand a third pill state?
3. Whose vocabulary is "provider"? If tools are the nouns, should providers exist in the interface at all?
