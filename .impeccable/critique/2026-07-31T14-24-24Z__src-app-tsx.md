## Design Specificity Verdict

**LLM assessment:** The token layer is genuinely authored: seam-shadow borders, wash-first status color, mono scoped to identifiers, and the truth-telling hint banners could only belong to this product. But the shipped IA contradicts the product's own north star. PRODUCT.md declares the integrations list is home and the status pill the most important pixel, yet Home renders exactly two cards: a Proxy toggle and a Direct Gateway card that dead-ends in Coming Soon. Tool data is already fetched (listTools, App.tsx:237) and used only for one Codex banner. The chrome is specific; the room is half-empty and partly interchangeable with any menu-bar VPN toggle.

**Deterministic scan:** 39 findings across 12 files. 36 are off-ramp literal font sizes, clustering into two systematic undocumented steps (12.5px in 18 places, 17px in 5, heaviest in Settings.tsx with 9) plus true one-off drift (15, 16, 19, 27px). 2 color findings (#000 in Onboarding.tsx:105,109) are false positives: they sit inside alpha masks where the color channel is never painted. The overused-font warning on Geist contradicts the locked brand choice and is also a false positive, but the scan surfaced a real discrepancy nearby: index.html loads IBM Plex Mono while index.css and DESIGN.md specify Geist Mono.

**Visual overlays:** Not available this run. The Chrome extension was not connected, so no browser inspection or overlay injection was possible; the dev server was started, verified serving, and cleanly shut down. Detector evidence is CLI-only.

## Overall Impression

A disciplined, honest visual kit wrapped around the wrong home screen. The craft floor is high (seam shadows, truthful banners, key custody made tangible) and the emotional ceiling is proven by the quit flow. But the product's stated core (per-tool routing status) is absent from the UI, the highest-stakes consent (root CA trust) gets the least ceremony, and the loyal daily user is greeted with red takeover alarm styling. The single biggest opportunity: make Home the tools-and-pills ledger the PRODUCT.md already describes.

## What's Working

1. **Truth-telling state banners.** The stale-address notice, Linux relaunch hint, and Codex drift heads-up admit when reality and config disagree, in plain language. Rare in this category and exactly the brand promise.
2. **Key custody made tangible.** Masked key with prefix-reveal and the confirmReveal step warning that reading it "may ask for permission" (Settings.tsx:387-410) renders the core product claim as interaction.
3. **A coherent, non-generic kit.** ui.tsx is small and consistent; seam shadows, mono on identifiers only, wash-backed pills. Avoids every locked anti-reference.

## Priority Issues

1. **[P1] Home is not the product.** No integrations list, no per-tool status pills; half the home is a ComingSoon placeholder (Home.tsx:123-134) while PRODUCT.md principle 2 names the tool list as the home view. Data already exists (listTools, App.tsx:237). **Fix:** replace the Direct Gateway placeholder with the tools list, each row carrying its truthful status pill. **Command:** /impeccable shape
2. **[P1] One-click destruction.** Reset (Settings.tsx:293-300, 423-431) wipes the account instantly; picking a Dev-mode gateway server (Settings.tsx:211-223) forgets the stored key and relaunches, also instantly. **Fix:** inline confirm panel (QuitConfirm pattern) stating exactly what is lost. **Command:** /impeccable harden
3. **[P1] CA trust is under-ceremonied.** Root-CA trust, the highest-stakes act in the app, is a one-line warning banner with a bare "Trust" text link (ProxyScreen.tsx:64-79). **Fix:** full slide-in panel explaining what the certificate does, where it lands, how to remove it; real accent button. **Command:** /impeccable harden
4. **[P1] Startup routing takeover is a false alarm engine.** Fires on every launch when routing is on with agents running, body copy in error red for a non-error state (StartupRoutingNotice.tsx:60), and its claim is often untrue for agents launched after the proxy came up. **Fix:** show only when routing state changed under running agents; informational copy in ink, error red reserved for failures. **Command:** /impeccable clarify
5. **[P1] The core control is inaccessible.** Switches lack accessible names (ui.tsx:55-80); the Home proxy card is a div role="button" handling Enter but not Space with an interactive switch nested inside (Home.tsx:46-82); takeovers do not trap focus; no visible focus rings. Fails the WCAG 2.1 AA commitment in PRODUCT.md. **Fix:** aria-labels, real button semantics, focus trap + aria-modal, focus-visible rings. **Command:** /impeccable harden
6. **[P2] Type ramp drift.** 36 off-ramp font sizes; 12.5px and 17px are de facto system steps used consistently but undocumented, plus one-off sizes (15, 16, 19, 27px). Also: index.html loads IBM Plex Mono while the system specifies Geist Mono, and fonts load from Google Fonts at runtime in a privacy-positioned desktop app. **Fix:** either promote 12.5/17px to the documented ramp or fold them into neighbors; bundle fonts locally; remove the stray IBM Plex Mono link. **Command:** /impeccable typeset (or audit)

## Cognitive Load

Failed 3 of 8 checklist items: visual hierarchy (placeholder card equals core control in weight), one thing at a time (FirstRun with key path expanded shows OAuth CTA + key form + help link + dev-mode picker on one 360px screen), working memory (restart hint auto-dismisses after 15s though the action is not time-bound; Launch-at-login advice requires recalling another screen's state). Settings (legacy-key variant) exposes ~8 actions at one decision point.

## Emotional Journey

- The peak drops the ball: Success.tsx tells you to turn on the proxy but only offers "Done", landing on Home with routing off.
- The scariest consent is the smallest control (CA trust banner).
- The day-30 loyalist gets cried wolf at by the red startup takeover.
- The quit flow is the emotional high point and the voice the rest of the app should learn from.
- Sign-in waiting states are calm and well-handled.

## Persona Red Flags

**Alex (Power User):** first launch hides the popover he clicked and opens a three-step tour window (App.tsx:270-276); update panel can take over the popover again; Title Case "Click Here to Locate Gate Connect" (Onboarding.tsx:196) and the Coming Soon card burn clicks; no shortcut for the core toggle.

**Sam (Keyboard/SR user):** unnamed switches announce as "switch, on" with no subject; Home proxy card ignores Space; no aria-live on loading or on hints that appear and vanish after 15s; takeovers leave the obscured screen focusable; cannot tell which switch is the master toggle without vision.

**The mid-task developer (project persona):** opens the popover asking "is my traffic going through Gate right now?" The header pill answers a different question per screen ("Connected" = routing in PopHeader but auth in Settings); may instead be greeted by an update or routing takeover; failures surface as raw backend strings (Home.tsx:121). The one answer this persona needs in two seconds is the least legible thing on screen.

## Minor Observations

- App.tsx:711 puts overflow-y-auto on the root, so headers scroll away on tall screens, violating DESIGN.md's fixed-header contract.
- Contrast below the stated floor: ink-4 (#7a7f93, ~4.0:1) carries meaningful 11px copy; gc-error (~3.9:1) is body-sized in banners.
- "Dev mode" environment picker sits on the first-run sign-in screen for every user (FirstRun.tsx:163-173).
- Onboarding step 1 makes claims the popover UI never substantiates afterward.
- Same refresh icon means both Switch organization and Sign out in Settings.
- The middot status grammar ("On · 2 providers") is a quiet, excellent authored detail; extend it rather than the four competing vocabularies.

## Questions to Consider

1. If the status pill is "the most important pixel on the screen," why does the shipped popover contain no per-tool pill at all, and which document is actually governing the build?
2. What does the day-30 loyal user, the person the success metric is named after, see each morning: reassurance, or a red full-screen takeover about the state they chose?
3. Would a security-literate developer click a bare "Trust" text link to install a root CA that can read their AI traffic, and if they hesitate there, has the app failed at the only moment reassurance was needed?
