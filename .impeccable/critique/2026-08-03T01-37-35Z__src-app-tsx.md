## Priority Issues

**[P0] The needs-trust member switch destroys the setting it looks like it would enable**
- **What:** `GroupDetail.tsx:173` renders `Switch on={member.routed}`, but `toggleMember` sends `onSetDomain(key, !member.domain?.enabled)`. In `groups.ts:81`, `routed = domain.enabled && proxyOn && caTrusted`. With an untrusted CA that is `true && true && false` = false, so the switch reads OFF while `enabled` is true. Clicking sends `false` and disables the domain. Verified independently three ways: A's browser run, B's probe, and the code. B's readings, verbatim: `aria-checked` is `"false"` initially, `"false"` after the first click, `"false"` after the second; the pill alternates "Needs trust" → "Not routed" → "Needs trust".
- **Why it matters:** This is the exact state an untrusted CA produces, which the app itself calls the usual answer to "why isn't my tool routing?" The user's remediation instinct destroys their own configuration, and the switch never moves to tell them. A screen-reader user gets no signal at all.
- **Fix:** Split display from intent. Give `GroupMember` a `desired` field (the persisted `enabled` / connected value) alongside `routed` (whether traffic actually flows). Drive `Switch on={member.desired}` and the click from `!member.desired`; let the pill keep carrying "Needs trust". Then add the missing remedy: a Trust action inside the needs-trust row, so the fix lives where the problem is named.
- **Suggested command:** `/impeccable harden`

**[P1] The takeover's heading never changes, and the destructive step wears the primary skin**
- **What:** B recorded all three steps. The `h1` is "Routing is off" on the informational step, the confirm step, and the outcome step; `aria-labelledby` points at it throughout. On step 1 the accent button is "Got it" (dismissal) with "Close them now" secondary. On step 2 the accent button is "Close everything", which interrupts the user's in-flight work, while "Cancel" is a bare 12.5px text button with no Button chrome. Settings' equally destructive "Reset everything" uses `error-deep`.
- **Why it matters:** DESIGN.md defines indigo as affordance and live state, the encouraged path; here it encourages data loss. Step 1 trains the reflex to hit the accent button, and step 2 puts destruction under that same reflex. Because the heading never changes, a screen reader entering the confirm hears no state change; only the outcome has a live region.
- **Fix:** Make the heading the question on step 2 so `aria-labelledby` changes. Give "Close everything" the error-deep treatment and make Cancel a visually equal secondary. One destructive grammar, not two.
- **Suggested command:** `/impeccable harden`

**[P1] The off-switch track fails WCAG 2.1 SC 1.4.11**
- **What:** `ui.tsx:95`. The off track is `bg-gc-line-strong` (#d4d7e3) on white: measured **1.44:1**, against a 3:1 requirement for a component state indicator. The on state clears it at 5.98:1 and is further carried by the indigo check glyph; the off state has no redundant cue. Five of these on Home.
- **Why it matters:** PRODUCT.md targets WCAG 2.1 AA with no dark-mode fallback, and this is the most-used control in the product. A low-vision user can see that a row is not on, which is weaker than seeing that it is off.
- **Fix:** Darken the off track to at least #9aa0b4 (3.05:1) or add a >=3:1 inset stroke. The pill dots also measure 1.80-2.12:1 against their washes, but each sits beside a text label that passes 4.5:1, so the dot is redundant rather than load-bearing; lower priority.
- **Suggested command:** `/impeccable audit`

**[P1] The ledger reports config tools as routed while the master is off**
- **What:** `groups.ts:59`, `memberFromTool` computes `routed` from `tool.status.kind === "connected"` alone, never gated on `proxyOn`, unlike `memberFromDomain` one function below. B's probe: with the header reading "Routing off" and the master card "Off · not routing", the Claude row simultaneously reports "Partly routed", "1 of 2 routing", and `aria-checked="true"`.
- **Honest caveat:** the probe ran against the harness, whose `proxy_disable` only flips `running: false` and never disconnects tools, so it does not model the backend sweep landed earlier this session. In the real app master-off now disconnects, and the row would read Not routed. The defect is still real: `snapshot_and_disable_everything` is best-effort per tool and logs failures rather than surfacing them, so a tool that fails to disconnect renders as routed under a dead relay, which is precisely when it is broken. Rarer than the probe suggests, and the same class of bug as the P0.
- **Fix:** Gate config members on `proxyOn` the way proxy members already are, with a distinct state for "configured but the master is off". Carry master state into `GroupDetail`'s header, which currently shows a green "Routed" pill with no master context at all.
- **Suggested command:** `/impeccable harden`

**[P2] Tour step 3 still ships screenshots of the previous product**
- **What:** `where-is-gate-connect-{macos,linux,windows}.png` show "Proxy · On - intercepting 3 domains", "Direct Gateway", and a "Connected" pill. Step 2's hero was regenerated this session, so the three-step tour now shows two different products thirty seconds apart. The regenerated hero also bakes in "Codex set up els…", advertising the truncation defect.
- **Why it matters:** First thing every new user sees, in a full window, teaching nouns the app does not have.
- **Fix:** Capture all three on their real OS; a headless Linux Chrome has no menu bar to photograph, which is why only step 2 could be regenerated. Widen the sub-line or drop the pill in the captured state so the hero stops advertising the truncation. `Onboarding.tsx:261` also marks the step dots `aria-hidden` with no text alternative.
- **Suggested command:** `/impeccable clarify`

## Questions to Consider

1. Why does Home never say "keychain"? Your first product principle says every screen should make the user feel where the key lives, and the screen users see 99% of the time is the one that doesn't.
2. If the master switch is off, why are four switches beneath it still live? Either it is a master and everything below goes quiet, or it isn't and it shouldn't be the heaviest card on the screen.
3. "2 of 7 routing" sets a denominator the screen's own controls cannot reach, because a group switch deliberately won't adopt a drifted config. Is the denominator everything installed, or everything Gate is willing to manage?
4. Both destructive confirms wear the friendly colour. If "Close everything" and "Reset everything" are both indigo or both quiet, what colour is left for "this will hurt"?
5. If a user opened this popover daily for a month, what would they learn about their own security posture? The tour makes three specific claims and the product never mentions them again.
