## What's Working

**The intent/reality split, carried to the pixel.** The switch says on, the pill says "Waiting on routing", and `aria-describedby` points the switch at the pill's sentence so a screen reader hears both facts. B verified the round-trip is clean.

**The change notice derives from the engine, not the click.** `noticeFor(turnedOn, engineRunning, engineWasRunning)` enumerates four outcomes from state, so no future toggle site can produce a wrong banner. "That turned routing on too" tells the user about a side effect they did not ask for.

**The exception-first ledger sub-line.** A broken member can never hide inside a count, and the family pill never rounds up.

## Priority Issues

**[P1] The certificate remedy fails silently, and hides behind an explanation**
- **What:** `trustCa` (`App.tsx:758`) and `untrustCa` (`:779`) call only `trackError` on failure, never `setProviderError`. B quoted both catch blocks and grepped the tree: no `ClassifiedError` with context `trust_ca` or `untrust_ca` reaches any screen. Their only consumer is `trackError`, which sends the title to PostHog. Separately, on Home the Trust button exists only inside the `caExplain` disclosure, behind a link labelled "What's this?".
- **Why it matters:** A cancelled admin prompt is the most likely failure in this app and it produces a UI that appears to do nothing. `toggleProxy`'s own comment warns that a swallowed error reads as "the toggle does nothing" - and that path surfaces it. This is the state that blocks every proxy-routed app.
- **Fix:** Give both the `setProviderError(classifyError(e, "trust_ca"))` treatment `toggleProxy` already has, and thread it into GroupDetail's in-place ErrorNote for the member-level button. Promote Trust certificate out of the disclosure, demoting "What's this?" to a caption beneath it.
- **Suggested command:** `/impeccable harden`

**[P1] Home has no vertical budget, so the daily view scrolls**
- **What:** B measured Home routing-off with four families at exactly **487/487** - zero headroom. With the change banner it is 556. Partial is 566 collapsed, 726 expanded. The banner is 69.5px plus a 10px gap; the "What routes through Gate" label is 33.8px.
- **Why it matters:** The settled position is that Settings may exceed the frame and Home may not. The One Room Rule is the layout's founding constraint and the primary screen breaks it in its most common configuration, with the fold cutting a family row mid-height so it reads as a rendering fault rather than as scrollable content.
- **Fix:** Reclaim ~90px. The banner is the cheapest target: one-line body with a right-aligned action is ~64px instead of 79.5. The section label costs 33.8px to say what the pills already say.
- **Suggested command:** `/impeccable layout`

**[P1] Identifiers, the one thing mono exists for, truncate in four places**
- **What:** The header host becomes `gateway.constellationgate.…` whenever the pill widens to "Needs trust"; `Settings.tsx:327` renders the same host in **13px sans** and truncates it; GroupDetail member hosts degrade to `api.an…`; Home sub-lines print `0 of 2…`. B measured all of them.
- **Why it matters:** DESIGN.md's Mono rule exists because identity and precision matter for these strings, and a truncated host in a popover that dismisses on click-away is unrecoverable. The proof it is fixable is one screen away: dev mode renders `gateway-staging.constellationgate.ai` complete at 10.5px mono in the same 360px.
- **Fix:** Settings Account renders the host as 10.5px mono on its own line, matching the dev-mode cards. GroupDetail moves the chip and host to a full-width third line out of the pill's column. When `groupSummary` returns an exception, drop the count rather than emitting `0 of 2…`.
- **Suggested command:** `/impeccable clarify`

**[P2] The one-time OAuth offer nags the user who already declined**
- **What:** Armed when `auth_mode === "api_key" && has_api_key && hasSeenTour() && !hasSeenOAuthOffer()`. B traced the sequence: the tour window opens *before* FirstRun and writes the flag on close, so by the time a user deliberately picks "Use an API key instead" and pastes a key, `hasSeenTour()` is already true. B also found the arming block sits inside the `isSignedIn` branch, so it is never evaluated during the install session at all - the offer appears on the next cold launch. The guard's comment claims it prevents exactly this.
- **Why it matters:** It reverses the user's stated choice on a screen they opened to do something else, and for the CI/headless persona the app explicitly endorses, the advice is wrong.
- **Fix:** Stamp `markOAuthOfferSeen()` when `connectWithKey()` succeeds in FirstRun. Anyone who chose the key on the first-run screen has answered this question.
- **Suggested command:** `/impeccable harden`

**[P2] One error slot in Settings, always rendered under "Account"**
- **What:** Both `ErrorNote` sites (`:379`, `:442`) sit inside the Account branch. Six handlers write the shared `error` state, three of them from controls under other headings: launch-at-login (This machine), switchServer (Gateway server), forget (Reset). B measured the slot at roughly y≈180 in a 626px scroll, so a failure from any of the three writes to a slot off-screen at the moment the user acts.
- **Fix:** Per-section error state, rendering the note immediately beneath the control that failed. GroupDetail already does this for member toggles.
- **Suggested command:** `/impeccable harden`

**[P3] Destructive actions take initial focus, on three panels**
- **What:** `useFocusTrap` focuses `focusables()[0]`. B read `document.activeElement` on mount: RoutingChangeNotice with `startConfirming` focuses **"Close everything"**; QuitConfirm focuses **"Disconnect tools and quit"**; the UpdatePanel takeover focuses **"Install & relaunch"**. A found two of these; B found the third.
- **Why it matters:** Confirms exist so the destructive choice is deliberate. A keyboard user who activated the Home banner with Enter and taps Enter again terminates every running agent.
- **Fix:** One hook, three sites: accept an optional `initialFocus` ref in `useFocusTrap` and point it at Cancel wherever the primary is `variant="danger"`.
- **Suggested command:** `/impeccable audit`

## Minor Observations

- The empty ledger shows "On · nothing installed to route" beside a banner offering to close apps that cannot be routing.
- The launch-at-login tip requires `banner === null && !error && !partial`, so the one feature that produces PRODUCT.md's success metric is hidden on most launches.
- The master card is mute while off: "Off · not routing" while two families read "waiting on routing". "Off · 2 waiting" is the fact that makes flipping the switch feel safe.
- `GroupDetail`'s master-off sentences still end "Turn routing on from Home" directly above a button that does it in place.
- `closeRunningAgents()` resolving nullish would freeze the confirm step, since `closed === null` is the not-yet-run sentinel. Coerce to `?? 0`.
- The tour's "Show me where Gate Connect lives" uses `bg-gc-accent-wash` plus accent text - a fourth button skin.
- Certificate "Remove" is ink-3, 12px, no underline or border, beside a four-line paragraph: the only destructive entry point with no visual weight.
- Expanding Dev mode inserts an `h2` "Gateway server" between Help and Reset, so the document outline gains and loses a section on a toggle.
- Escape dismisses from Settings and Group but not from Home, against menubar convention.
- `gc.oauth-offer.v1.seen` is keyed to the webview, so switching gateway servers inherits the flag.
- The OAuth offer's 13 background focusables stay natively tabbable under `aria-hidden`; containment relies on the `keydown` listener rather than `inert`. The trap does work - this is a hardening note, not a break.

## Questions to Consider

1. Twenty error hints end in "the details below help when reporting it", with no report channel, no support link and no way to copy the payload out of a popover that dismisses on click-away. Is that sentence a promise or decoration? If a channel is not coming, change the copy.
2. `classifyError` has written, tested strings for `trust_ca` and `untrust_ca` that no screen renders. What else is tested-but-unrendered, and what does a green suite mean if it can cover a user-facing silence?
3. Home is exactly 487px with four families and no banner. What happens when Gate ships a fifth provider? Is the ledger's job to list families, or to list what needs attention with the healthy ones collapsed?
4. FirstRun is the only screen where a plaintext credential sits in the DOM, and the only screen that never mentions the keychain, because the footer is gated on a credential already existing. If credentials are the product, why is the reassurance gated on already having one?
5. Three surfaces say "Turn on routing" at three different weights, plus prose sending the user elsewhere. The master is settled as a control - so which of those three is the canonical one?
